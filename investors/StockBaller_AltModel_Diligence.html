Section 2 — SQE v4: The AI Prediction & Pricing Engine

The AI Engine That Prices
Every Athlete Token

The Sports Quantification Engine (SQE v4) is the proprietary model at the centre of this platform. It does two things no competitor has built: it converts real-world athlete performance into a deterministic, on-chain-verifiable price in real time — and it generates a prediction signal that lets users (and the subscription product) forecast the next price move before the match ends.

What "AI" Means Here — Precisely

Pricing Layer Deterministic Model

The pricing formula is a calibrated, weighted algorithm — not a neural network. Given identical inputs it always produces identical outputs. This is intentional: it makes every price move auditable, legally defensible, and reproducible by any third party.

Calibrated on: 2,400 WC 2022 player-match records. Version 4 of 4 iteration cycles.

Prediction Layer ML Signal

The prediction model is a supervised classification model — trained on historical SQE outcomes — that outputs a probability distribution over three outcomes: Price Up / Flat / Down in the next match. This is the signal sold in the subscription tiers.

Training data: 4 SQE formula versions × 2,400+ match records = 9,600+ labelled outcomes.

SQE v4 — Master Pricing Formula

Final Price = (Market_Base × Decay_Factor) + (Yield × Trajectory × 3) Market_Base Starting reference price per player (FIFA rank + career stats seed) Decay_Factor 0.95 ^ weeks_inactive → benched/injured players lose value over time Yield Weighted match event score (goals, assists, cards, clean sheets) Trajectory EMA of last 3 match Yield scores → form context, not just one match × 3 Amplification constant → calibrated on WC 2022 dataset Stage Multiplier: Group 1.0× | R16 1.25× | QF 1.5× | SF 2.0× | Final 3.0×

Yield Event Weights — Full Table

Match EventYield PointsRationale
Goal scored+3.0Highest single positive event. Core value driver for attackers.
Assist+1.5Half-weight of goal. Direct contribution to scoring.
Clean sheet (GK/DEF)+1.0Positional context — rewards defensive discipline.
MOTM award+1.0Official match award — independent editorial validation of performance.
Penalty won+0.5Partial contribution — not a direct goal but a high-value action.
Yellow card−0.5Minor negative. Discipline signal — next yellow = suspension risk.
Penalty miss−2.0High-visibility failure. Significant negative sentiment driver.
Red card−3.0Maximum negative. Player exits match + misses next game (Decay accelerates).
Own goal−1.5Significant error. Treated as negative contribution to team performance.

Prediction Model — How It Works

Input features (per player, per upcoming match): 1. Current Trajectory score (EMA of last 3 Yield values) 2. Decay_Factor (weeks since last match) 3. Opponent defensive rating (derived from opponent's last 5 defensive Yield conceded) 4. Tournament stage (categorical: Group / Knockout) 5. Days rest since last match 6. Historical Yield variance (consistency score — high variance = unpredictable) Output: P(Price Up) = probability next match Yield > current Trajectory P(Flat) = probability next match Yield ≈ current Trajectory (±10%) P(Price Down) = probability next match Yield < current Trajectory Model type: Gradient Boosted Trees (XGBoost) Training set: 2,400 WC 2022 labelled outcomes + 1,200 WC 2026 (live, expanding) Validation: Rolling out-of-sample test on each WC 2026 match as data comes in

Why This Is Defensible IP

The SQE model is the only performance-pricing oracle for footballer tokens on any EVM chain. Building an equivalent requires: (1) designing and iterating the formula over multiple versions, (2) curating and labelling 2,400+ match records, (3) training, validating and deploying the ML layer, (4) wiring it to a live sports data API with correct stat parsing, and (5) connecting the output to a verified on-chain oracle. No competitor has done steps 3–5 together. The WC 2026 dataset created during this tournament is a proprietary training asset that grows more valuable every match day.

Section 3 — On-Chain Fee Architecture & Smart Contract Revenue

How Every Trade Generates
On-Chain Revenue

In this model, platform revenue is collected directly by smart contracts on Base L2 — not by the platform as a custodian. No user funds pass through a company bank account. The fee is extracted at the contract layer, accumulated in a treasury multisig, and withdrawable by the platform at any time. This is the technical and legal distinction that removes the need for an e-money licence.

Fee Collection Flow — Buy Transaction

User connects wallet (Openfort embedded or MetaMask/Coinbase Wallet) ↓ User calls AthleteVaultV2.buy(tokenId, amount) — sends USDC from their wallet ↓ Contract calculates: platformFee = tradeAmount × 0.01 (1%) ↓ Contract splits: netTokenValue → credited to user's on-chain token balance (ERC-1155) platformFee → forwarded to TreasuryWallet (Gnosis Safe multisig) ↓ TradeExecutedEvent emitted → picked up by backend → leaderboard + activity feed update ↓ User receives ERC-1155 token in their wallet — fully self-custodied

Fee Collection Flow — Prediction Market Settlement

User calls PredictionMarket.placeBet(matchId, outcome, stakeAmount) ↓ Stake locked in contract escrow until match result finalised ↓ SQE backend posts result: PredictionMarket.settle(matchId, result) ↓ Winners receive: payout = stakeAmount × odds × (1 - 0.10) (10% house margin) ↓ 10% margin → forwarded to TreasuryWallet (same Gnosis Safe multisig) ↓ No platform custody at any point — contract holds escrow, not the company

Treasury Architecture

Gnosis Safe Multisig Base Mainnet

All platform fees accumulate in a 2-of-3 Gnosis Safe multisig on Base. No single key can withdraw funds. Standard for Web3 treasury management — used by Uniswap, Aave, Compound.

Keys held by: Founder (1) + Technical Lead (1) + Hardware Wallet Cold Store (1).

Cost to deploy: <£0.50 one-time gas. No ongoing fees.

Revenue Visibility Public On-Chain

Every fee collection is a public blockchain event. An investor can verify accumulated treasury balance and all fee transactions directly on Basescan — no need to trust platform-reported figures.

This is a structural advantage over any fiat-based business: revenue is independently auditable by anyone with the contract address.

Real-time treasury balance: readable via ethers.js or Basescan.
